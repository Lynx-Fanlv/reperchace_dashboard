# 预计购药分析看板（网页共享版）

针对 **百泽安 / 百悦泽** 两个品种的患者，融合 **销售明细 + 随访任务 + 患者用药周期** 三张表，
在浏览器内自动计算「应购药日期」，匹配距离应购药日期最近一次的随访记录，
综合判定患者状态，并按 **品种 / 随访人 / 医院 / 状态 / 应购日期范围** 多维筛选。
支持 **脱敏 / 不脱敏两种网页快照** 与 Excel 名单导出，可直接离线打开或外发分享。

- 纯前端、无后端、无网络请求：数据从不离开本机。
- 归一化逻辑复用自 `followup_dashboard/webapp`（关键字启发式列映射，**表头变化也能兼容**）。
- **统一上传 + 自动识别**：一次拖入/选择多张表，按表头自动识别类型；已选文件列表可确认/删除，
  开始分析后上传窗口仍保留，可增删后再次分析。
- 姓名 / 电话 / 医生支持**展示层脱敏切换**，导出与快照亦有独立脱敏选项；患者姓名脱敏方式四选：**保留首字 / 保留首+末字 / 仅会员号（患者列显示会员号，医生列隐藏）/ 全部隐藏**（销售表需含「会员号」列）。
- 表格末列支持**手动填写跟进备注**（仅「应回购 / 已逾期」两类显示填写窗口），内容随快照一并保存。
- 适合「团队共用 + 外部脱敏网页快照分享」场景。

## 数据需求（三张表）

| 表 | 关键列（关键字自动识别） | 说明 |
|---|---|---|
| 销售明细（必需） | 销售时间 / 商品名称 / 会员姓名 / 会员电话 / **医疗单位** / 药房名称 / 处方医生 / 处方科室 / 适应症 | 每行一次购药；应购药日期由此计算；医生列取自「处方医生」 |
| | **小票号**（可选，仅用于自动去重） | 见下方「销售明细自动去重」；缺失不影响其他功能 |

> **医院列只认「医疗单位」**（精确匹配，不做关键字模糊匹配）。销售明细里若另有「首诊医院 / 就诊医院 / 医院」
> 等列，**一律不取**。若底表没有「医疗单位」列，患者列表的医院列会留空。医院筛选、导出列同此口径。
> 科室取自「处方科室 / 科室 / 就诊科室」，医生取自「处方医生 / 开单医生 / 医生」，这两个字段仍走宽松匹配。
>
> **医院 / 科室 / 医生 取「该患者该品种销售时间最末次那条记录」的值**（三个字段同一口径，不取文件末行——
> 销售明细常按销售时间降序导出，末行反而是最早那次购药）。**末次那条为空就显示为空**，不会回退到更早
> 那次的非空值，因此「界面显示的值 ≡ 末次记录的值」，可拿销售明细直接核对。
> 同一天有多条（一笔购药被拆成多行）时，用该日内最后一个非空值补齐。
> 药房筛选生效时，只在该药房的购药记录里取末次（与其他列口径一致）。
>
> **患者身份 = 姓名 + 电话（两者都参与去重）**。同名不同电话（**重名**）视为两个不同患者；
> 同一号码被不同姓名共用（家人共用号码 / 前台代留）同样视为两个患者。只有姓名与电话都相同才合并为一人。
> 电话支持任意格式，比较时只保留数字（`138-0000-0001` 与 `13800000001` 视为同一号码）。
> 姓名与电话都为空的行无法区分，会归入同一个「未知」患者。
> **重名保护**：随访表常缺电话、只能按姓名匹配；若某姓名在销售数据里对应了多个电话（即重名），
> 该姓名**不再按姓名回退匹配随访**——宁可不匹配，也不会把同名他人的随访安到这个人头上
> （状态与未购药原因不会被串到另一个人身上）。姓名唯一的患者仍照常按姓名匹配。

| 随访任务（可选） | 任务状态 / 患者(患者姓名) / 联系电话(电话号码) / 计划执行时间(计划执行日期) / 执行时间 / 产品(药品名称) / 服务摘要(任务摘要·任务类型) / 执行人 / 随访小结(患者反馈内容·备注) | 多模板合并大表亦可；**新旧版表头措辞自动兼容**（括号内为「历史任务」类导出用词）。信号列亦双兼容：「患者目前的用药状态 / 用药周期状态」「是否判定易脱落 / 是否脱落·是否确认脱落」「判断为易脱落的原因 / 脱落原因」「推迟用药的原因 / 未按计划持续用药原因」 |
| 患者用药周期表（可选） | 患者 / 用药周期（天） | 按患者覆盖周期；表中没有的患者用品种标准周期 |

> 用药周期优先级：**周期表 > 品种标准周期**。标准周期**只按上传数据中实际出现的品种生成**
> （不写死内置商品）：内置品种族用内置默认值（百泽安 21 天 / 百悦泽 28 天 / 索托克拉 28 天），
> 出现的新品种默认 30 天；界面「判定配置」栏**只显示数据中出现的品种**并允许修改，
> 周期表未覆盖的患者使用对应品种标准周期。
> ⚠️ 周期表只有「患者」列、没有电话列，因此**重名患者会共用同一条自定义周期**，无法在周期表内区分；
> 若需要区分，请让这些患者使用品种标准周期（即不写进周期表）。

## 销售明细自动去重

多份导出报表常互相重叠（不同日期导出、文件名带 `(1)(2)` 的副本），直接合并会把同一笔购药算多次。
**分析开始时自动去重**，无需人工挑选文件。

**判定依据 —— 以下 5 个字段全部相同才视为重复：**

| 字段 | 说明 |
|---|---|
| 小票号 | 天然凭据；销售明细里的「小票号 / 小票编号 / 票据号 / 销售小票」列自动识别 |
| 销售时间 | 到日 |
| 商品名称 | 原始商品名 |
| 药房（门店） | 取「药房名称」列 |
| 销售数量 | — |

**口径要点：**

- **只认「小票号」，不读「订单号」**（订单号可能一单多行，容易误删）。
- **5 个字段必须全部一致**才算重复。同一张小票里同一商品分了多个计价批次（数量不同、或不同时间扫码），
  会被当作不同行**全部保留**，不会误删真实购药。
- **没有小票号（整列缺失，或该行为空）的记录不参与去重，一律保留**。
- 同一重复组内保留**信息最全**的那条：非空字段数 → 有会员号 → 有电话 → `_row_id` 字典序兜底
  （与文件上传先后顺序无关，结果可复现）。
- **保留的行停在它原本的位置**，不打乱表格顺序。
- **小票号只用于去重，不参与任何业务计算、不出现在列表、不进导出与快照**。

**界面提示**：分析后顶部出现一行提示条 —— `已自动去除 N 条重复销售记录（M 组）：A → B`，
点「查看详情」可展开被移除行的明细表（小票号 / 销售时间 / 商品名称 / 药房 / 数量 / 来源文件，最多显示 200 条），
点 `×` 可关闭整条提示。**没有重复时提示条完全不出现。**

> 实测本机 36 份真实销售明细（73,483 行）：小票号填充率 **100%**，识别出 21,472 个重复组、
> 可删 26,189 行（35.64%），其中 **96.5% 的重复组是跨文件重复**。

## 本地留档（OPFS，下次不用重新上传）

反复导出销售明细很麻烦。看板会**把本次分析用到的销售明细按品种存进浏览器本地**，
下次只上传新品种的增量文件即可，历史数据自动带出来。

- 存储位置：浏览器 **OPFS**（Origin Private File System）→ `<origin>/留档/销售/<品种>/sales.json`
- 触发时机：**只有「本次上传的品种在本地已有历史」时才弹窗询问**；本次品种全无历史 → 不弹，直接只算本次
- 弹窗内容：本次上传的品种（**默认勾选**）+ 本地留档里的其他品种（**默认不勾，可点选加入**）
- **时间段细化**：勾了品种后，点该行右侧「选择时间段」可展开**按月份的清单**
  （如 `2026年9月 30条 / 2026年8月 44条 / 2026年7月 56条`），只勾其中几段加载即可，
  并实时显示 `已选 N / M 条`。默认全选（= 全取，与旧行为一致）。
- **只带销售明细**：随访与用药周期**只用本次上传的**（它们有时效性，本次结论优先）
- 合并后**统一走去重**，历史与本次重叠的行自动去掉，不会重复计算
- **数据被浏览器回收 / 读取失败 → 静默当「无历史」**，不打扰用户
- 顶部会注明 `· 已并入历史：百悦泽 30/130条`，让你清楚本轮算了几份数据

> ⚠️ **存储按 origin 隔离**：`file://` 打开（双击 index.html）与 `https://` 打开（GitHub Pages）
> 是**两套独立存储，互不连通**。想持续用留档，请固定一种打开方式。
>
> ⚠️ **配额是 best-effort**：实测单个 origin 配额约 10 GB，但 `navigator.storage.persist()`
> 在浏览器里通常返回 `false` —— 磁盘紧张时浏览器有权清理。**所以留档只当便捷缓存用，
> 不要当成唯一数据源**，原始报表该留还得留。

### 留档的显示名：品种名 + 销售时间起止

留档在**界面里**显示成「品种名 · 销售时间起止」，例如 `百悦泽 · 26.7.1-26.9.16`
（起止取自该品种留档记录的 `sales_time` 最小/最大值）。

> ⚠️ **目录名仍然是「品种名」**（如 `<origin>/留档/销售/百悦泽/sales.json`），
> 日期只作为**显示名**。原因：改目录名会让用户**已有**的留档全部读不到（等于一次静默丢失）。
> 显示名与目录名分离，既满足「一眼看出这份留档覆盖哪段销售时间」，又保证旧留档无损。

### 留档写回 = 「只增不删」并入

上传后的回写是**并入**而非覆盖：旧记录保留，新键追加，同键择优替换。

> ⚠️ **历史教训**：这里曾是「整品种覆盖」——写的是「历史 + 本次去重后」的全集。
> 该设计隐含假设「本次上传 = 该品种的全量」，但假设不成立：
> 用户只上传某品种的一个月数据时，写回会把留档从「8月10条 + 9月1条」覆盖成「只有9月的1条」，
> 历史被**静默丢弃**。改为「只增不删」后，上面这个场景实测从 1 条变为 **11 条**（不丢）。
>
> 代价：若去重键抓不住某类差异（如数量 `"1"` vs `"1.0"`），这些行会逐轮累加。
> 因此提供了下面的**留档管理器**给用户一条「看得见、能自己清」的通道。

### 本地留档管理器（顶部「本地留档」按钮）

OPFS 是浏览器**私有沙箱**，磁盘上**没有可双击打开的文件夹**（浏览器刻意的隔离），
所以提供等效能力：

- **查看**：列出每个品种、条数、更新时间，以及销售时间跨度（`共 N 个品种 · M 条 · 销售时间 26.7.1-26.9.16`）
- **删除**：逐品种删除（二次确认）
- **导出备份**：把全部留档下载成一个 JSON（文件名带时间跨度，如 `本地留档备份_26.7.1-26.9.16_2026-09-29.json`），用于留底或换电脑
- **全部清空**：二次确认；品种数 ≥2 或记录 ≥100 时额外要求手输「清空」二字

**实测**（真实 Chrome，销售明细 95 条 / 93 条去重后）：写入 → 刷新页面 → 读回完全一致；
只上传新品种时**不会删掉**其他品种的留档。

**验证**：
- `node tests/_test_archive.js`（92 项：内存假 OPFS 读写往返 + 接入点静态断言）
- `node tests/_test_archive_merge.js`（9 项：「只增不删」合并语义）
- `node tests/_test_archive_mgr.js`（5 项：管理器交互）
- `node tests/_test_archive_range.js`（96 项：日期跨度 / 按月分段 / 按段加载）
- 真实浏览器端到端 `node tests/_cdp_archive.mjs "<A.xlsx>" "<B.xlsx>"`（32 项）
- 真实浏览器端到端 `node tests/_cdp_archive_range.mjs "<含多月数据的.xlsx>"`（34 项，含截图）

## 核心计算口径

1. **应购药日期** = 该患者该品种最近一次购药日期 + 用药周期。
2. **随访匹配** = 取应购药日期 **之前最近一次** 随访（同品种优先；若之前没有，取之后最早一条；
   优先「已完成 / 有执行时间」的真实随访，避免未执行任务干扰）。
3. **状态判定**（周维度状态机）。时间基准 = **参考日期**（默认今天，可手动改以回看历史周）所在**自然周（周一~周日）**；视图可选 **上周 / 本周 / 下周**（单选，默认本周），所选周即状态判定的时间窗口：
   - 三个主状态：
     - **应回购**（所选周应购清单）= **应回未回 + 应回已回**：
       - **应回未回**：应购药日落在所选周内、当周未购药（该催的名单：上周=该买没买，本周=待催，下周=提前看）。
       - **应回已回**（**购药事实最优先**）：**所选周内有购药记录**（本周该买也买了 / 提前买都算）。
           应购药日期列显示「预判应购日」（= 倒数第二次购药日 + 周期，≥2 条购药记录时），
           并标注 **提前 N 天 / 延后 N 天 / 按时**；仅 1 条购药记录（无预判基准）时该列显示 —。
     - **已逾期**：应购药日在所选周之前（且当周未购药）。
     - **未到期**：应购药日在所选周之后（且当周未购药）。
   - 一句话：**当周购药 = 应回已回；应购日落在所选周且未购 = 应回未回；两者合计 = 应回购**（周选择器下显示所选周的具体起止日期）。**名单中「应购药日期落在所选周」的患者置顶显示并带浅金色特殊底色，导出 Excel 同步整行浅金底**。
   - **应回购细分**：状态卡片下方「应回未回 / 应回已回」chips 可点选筛选；行内状态列同时标注主状态与细分。
   - **未购药原因标注（所有患者均可点选）**：「未购药原因」列点击展开分类选择（层级：父类 ▸ 子类），为患者标注未购药原因；**自动判定（随访文本）预填为初始值**，人工点选覆盖（快照保存）。
     无标注时按状态显示占位：应回已回 =「已购药」、未到期 =「—」、其余 =「未标」。原因列可筛选（状态卡片下方 chips）。
   - **原因分类可维护**：整体小结面板「管理分类」→ 增删改分类 / 加子类 / 恢复默认；**「未购药原因」列选项与小结文案同步跟随**。
4. **用药周期取值优先级（列表内可直接改）**：**① 该患者在该品种上的人工设置**（列表「周期」列点击修改）
   → ② 周期表（患者用药周期表自定义值）→ ③ 品种标准周期（周期控件中的值）→ 30 天兜底。
   - **粒度 = 患者 × 品种**：同一患者的两个品种互不影响。
   - 列表「周期」列**点击即改**：回车保存、Esc 取消、**清空即恢复**为周期表/标准周期；
     非法值（≤0 或非数字）不写入。
   - 已单独设置的行：周期值显示为**实心色块**，下方带一条细色线标识。
   - 修改后 **应购药日期、距今天数、状态分类、小结统计实时重算**。
   - **随快照一并保存**：接收方看到的周期与发送方一致。
5. **筛选**：状态分类 / 应回购细分 / 未购药原因 / 品种 / 医院 / 药房 / 随访人 / 关键词与周视图叠加生效（交集）；**状态卡片计数随 品种 / 医院 / 药房 / 随访人 / 关键词 筛选实时变化**（点击状态卡片本身不改变计数基数）；**整体小结统计范围跟随 医院 / 药房 筛选**（多选=或；品种由 chips 切换）；「重置筛选」回到默认「本周 + 今天」。
6. **跟进备注**：仅「应回购 / 已逾期」两类患者显示填写窗口（其余大类显示 —）。
7. **整体小结**（按品种分别总结，随数据自动生成，可复制）：
   - **统计「所选周」**：跟随顶部 上周/本周/下周 视图（周一~周日完整周，与状态机同一范围；点上周即总结上周）；不受周期控件（近7天/自定义遗留项）影响；品种可点选切换，各品种独立小结。
   - 内容：本周应回购 / 应回已回 / 应回未回人数；**未购药原因 = 患者明细「未购药原因」列标注的汇总**（统计范围 = 应回未回 + 已逾期；层级父类人数 = 子类之和；分类顺序/增减由「管理分类」维护）；下周预计复购 / 正常回购 / 推迟（附原因）。
   - 口径（与状态机完全一致）：应回购（总集）= 应回未回 + 应回已回；应回未回 = 下次应购日（最近购药 + 周期）∈ 本周且当周未购；应回已回 = 当周有购药记录（含提前购药者）。下周预计 = 下次应购日 ∈ 下周（下个自然周）的患者，按随访信号分正常/推迟，脱落不计入复购。

## 快照（导出）功能说明

- **脱敏快照**：姓名、电话、医生已脱敏，文件中不含明文个人信息，可安全外发。
- **不脱敏快照**：含明文个人信息，仅可分享给可信接收方（生成前有隐私风险提示）。
- 快照为单文件 HTML，离线双击即可打开，只读展示当前筛选后的名单。
- **按品种范围导出**：点「下载快照」后先弹出**品种勾选弹窗**（默认勾选当前筛选出的品种，可全选/清空改选），
  只有被勾选的品种数据会被写进文件——可只把品种 A 的名单发给他人，对方拿不到其他品种的任何数据。
  文件名会带上品种标识：单品种 `预计购药名单_百泽安_脱敏快照.html`、2~3 个用 `+` 连接、更多则标 `_多品种`。
- **快照内仍可按品种筛选**：筛选面板保留，但选项只含该快照内嵌的品种（不会出现被排除的品种）。
  因此接收方能在收到的范围内自由切换，却无法看到范围外的品种。
- **快照不显示脱敏切换栏**：打开快照后**沿用生成时的脱敏状态**，界面不再提供脱敏相关开关，避免误改后外发。
- **快照不含「整体小结」**：小结的统计口径依赖本地销售明细，快照中无法重算；为避免接收方按错口径理解，
  导出的快照不再包含小结面板与小结文本（分类维护面板仍随快照保存，以保证「未购药原因」显示中文标签而非内部 key）。
- **手动填写的「跟进备注」与「下钻状态手动修正」会随快照一并保存**，打开快照仍可见。
- **Excel 导出（带样式）**：表头加粗 + 品牌色底，状态列按大类着色（应回购红/已逾期橙/未到期蓝），应回购细分（应回未回红/应回已回绿）、
  下钻列按子状态着色、逾期「距今天数」标红加粗；分脱敏 / 未脱敏两种，含医生列、下钻子状态列与跟进备注列。
  导出基于 exceljs（`vendor/exceljs.min.js`），仍为纯前端、数据不出本机。

## 长文本与列宽（排版）

药品名、医院名等长文本**不再把表格行高与列宽撑开**：

- **列宽固定**：`table-layout: fixed` + 按列语义下发的 `colgroup` 宽度档位（`c-narrow` / `c-tel` / `c-date` /
  `c-mid` / `c-prod` / `c-wide` / `c-note`）。用**百分比**而非固定 px —— 19 列全显时若写死 px，
  合计会超过容器宽度而产生横向滚动；百分比则无论显隐哪些列都恰好铺满，各列相对优先级不变。
- **长文本单行截断**：`.clip1` 溢出省略；**悬停显示全文**（`title`）；**点击可展开/收起**看完整内容。
- **表头精简**：列窄时表头会逐字竖排，故表头文字取短名（`购药数量`→`数量`、`应购药日期`→`应购药日` 等），
  并给 `th` 加 `word-break: keep-all`。
- **日期列不换行**：日期与小标（`还有N天` / `逾期N天`）包在 `.due-cell`（flex，`align-items: baseline`）内，
  窄列下不会各占一行把单元格高度翻倍。
- **`inline-block` 陷阱（已修）**：窄列中 `inline-block` 元素若超出可用行宽会**另起一行**，
  叠加 `vertical-align: baseline` 的下沉空间，使该行盒高达 42px（其他列仅 19px），进而把整行从 34px 撑到 **57px**。
  `.cycle-edit` 与 `.ce-dot` 均已改为 `display: block`。

> 实测：行高 **71px → 38px**（设置周期后 42px），横向溢出 **556px → 20px**。
> 真实浏览器几何验收见 `tests/_geom_run.mjs`（22 项）。

## 手动调列宽 / 行高（像 Excel 一样）

列表上方有「视图」工具条，两个都是**本会话有效、刷新即恢复默认**（不写 `localStorage`、不进快照）：

| 操作 | 方式 | 口径 |
|---|---|---|
| 调列宽 | 拖动**表头右边缘**（悬停显蓝线） | 拖过的列固定为 px（48~640 夹取），未拖过的列继续按百分比档位自适应 |
| 调行高 | 「行高」滑块，28~72px | 一次调所有数据行，实时生效 |
| 复位 | 「恢复默认」按钮 | 列宽回到百分比档位 + 行高回 34px |

- **末列无把手**：最右一列没有可拖的边界，且把手会与纵向滚动条抢鼠标。
- **拖窄一列的边界**：整表 `width:100%`，且其余列有 `min-width`，浏览器会把富余宽度回填，
  故实际能压到的地板**高于** `COL_MIN`（48px）——实测 `医院` 列约 100px。这是布局约束，不是夹取失效。
- **行高的真实地板**：`td` 的 `height` 只是下限，真正卡住高度的是「上下 padding + 内容行高」。
  默认上下各 7px、内容约 19px，合计 38px —— 若只改 `height`，滑块在 28~37px 区间会「能动但没反应」。
  故上下 padding 也做成变量 `--row-pad`，由 `setRowHeight` 联动压缩：`pad = clamp(2, (h-21)/2, 7)`。
  实测 28→31px、40→40px、72→72px，全程单调响应。
- **不用 `setPointerCapture`**：一是 `renderTable` 会重建 `thead`，被捕获的节点会变成游离节点；
  二是捕获期间后续 `pointerdown` 会被重定向到捕获元素，**实测第二次拖拽直接收不到事件**（静默失效）。
  改走 `pointerdown`（把手）+ `pointermove/up`（document）+ 一次性解绑。
- **快照模式下整条工具条隐藏**：快照是冻结的报告，展示口径应统一。

> 真实浏览器验收见 `tests/_view_run.mjs`（38 项：着色色值、拖拽事件流、边界夹取、行高单调性、不持久化）。

## 「距今」列着色

单行数值 + 按语义着色，**不换行、不加文字小标**。色语义与「应购药日」列的小标**同源**，
保证全表读法一致：

| 情形 | 显示 | 颜色 |
|---|---|---|
| 应回已回 | `N天前已购药` | 绿 `--good #0f9d6b` |
| 逾期 | `-N` | 红 `--bad #e03131` |
| 还有 N 天 / 今天 | `+N` / `今天` | 蓝 `--blue #3b5bdb` |

- 必须单行（`.days-num` 带 `white-space: nowrap`）：窄列折行会把该单元格高度翻倍并撑高整行。
- **导出 Excel 同步着色**：`exportDaysFont()` 与列表同色语义；无值返回 `null`，保持默认字体不误染。
